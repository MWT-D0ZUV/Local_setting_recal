# 设定与风格自动召回 1.1.2

1.1.2 优化事实、语录和旧批次的相关性筛选。普通闲聊不再无条件启动全库事实语义查询；事实需要规则、通用词或非 Q 文档标题/关键词触发。事实候选排除 Q 语录，风格只选 Q 语录；同时含“文档分类”和“用途说明”的简介片段被排除。风格查询优先使用当前消息情境。升级保留已加载快照、向量、消息去重和个人配置，每 20 条一批的行为不变。

MaiBot SDK 插件：手动加载 TXT/Markdown 资料，按真人文本消息批次检索，将相关短片段供 Planner 和 Replyer 复用。完整离线回归已分别在 Host 1.3.18 / SDK 2.19.0 与现场 Host 1.3.19 / SDK 2.21.0 通过；SDK 声明范围 2.19.0–2.21.0。中间版本未逐一验证；声明范围外未验证。

**分享版必须先按自己的角色、文档和会话调整。** 包内配置使用通用查询、不含本机目录或真实文档。源码默认规则保留了本次适配示例；不要将示例人物关系当作自己的设定。可将 AI_RULE_SETUP.md 交给 AI，按你的资料生成规则后自行核对。

## 开始使用

1. 将完整插件目录放入 MaiBot 的 plugins，等宿主加载；升级前备份原插件。到插件设置填写“默认参考目录”（绝对路径），或直接在文档管理页粘贴路径。
2. 打开该插件的“参考文档管理”扩展页，点击“浏览目录”，勾选具体文件，再点“加载选中文档”。浏览只列出文件名，不读正文；只有加载才读取所选文件。
3. 需要语义检索时，确认宿主 embedding 任务可用，再点“构建向量索引”。此按钮会把已选片段发送给宿主配置的 embedding 服务，可能计费。构建成功后，聊天检索也会将查询文本交给该服务。
4. 默认每 20 条有效真人文本消息一批；可设 1，或开启“跟随宿主新增消息门槛”。同步的是 a_memorix.integration.heuristic_memory_recall_min_new_messages，不是上下文窗口大小。

没有周期扫描或聊天时读源文件。原文件修改、新增、删除后，需要再次浏览、勾选并加载；向量需重新构建。只保存默认目录不会读取新目录，也不会替换已加载资料。管理页浏览路径与已加载路径分开显示，浏览其他目录不会清空当前资料。

重启只恢复插件私有的已加载快照及有效向量，不重新扫描原目录。手动加载空选择可清空快照。修改默认目录仍可恢复此前明确加载的快照；真正换库请在管理页重新加载。原文件保持只读。

## 文档格式与命名

- 仅目录直接子级 UTF-8 / UTF-8 BOM 的 .md、.txt；不递归，不支持 PDF/DOCX，不跟随链接。
- 默认排除 00*，在打开前过滤；可修改排除规则。
- F 开头建议放事实/形象/关系，N 开头建议放经历，Q 开头放发言语录。事实检索排除 Q 语录，其他已加载资料均可作为事实候选；风格检索固定只选 Q*.md / Q*.txt，不再提供文件模式编辑框。大小写按平台匹配，建议统一用大写前缀。
- 其他文件名也能作为事实文档。建议写清 Markdown 标题，并加“关键词：主题一,主题二”。不是必须只有 F/N/Q 三种文件。
- 默认最多 40 文件，每份 128 KiB、总计 1 MiB，可在设置的范围内调整；管理页一次最多勾选 40 文件。

## 批次、去重与生效时机

仅在 Planner/Replyer 请求前收集宿主已落库的真人文本，按会话计数。图片、转发内部文字、指令、通知不计入；不是每收到一个事件就立即查。初次只纳入最近一批，避免启动时回查全部历史。

满批后启动后台任务，逐条运行一次检索流程，包含至多一个事实查询及一个风格查询；向量不可用/无结果时可使用关键词，若打开宿主回退还可能再调用宿主查询。因此“每条一次”指不重复安排同一条消息，不等于每条只发一个 API 请求。

Planner/Replyer 共用持久的消息 ID 记录和已完成结果。批次任务不阻塞模型，本轮回复可能赶不上；下一次请求会复用精确消息的结果，或最近 5 分钟内最新同版本批次中与当前话题匹配的缓存。跨消息匹配比较原消息与当前消息，不再用长资料正文的偶然重词判断；最多复用一条事实和一条风格参考。可在“跨消息参考复用有效期”设置中调整，0 为关闭，精确消息结果仍保留。未满下一批时不会为新消息发起检索。要求更及时可设批次为 1，但后台模式仍不保证首个请求等到结果。

失败、超时、重启中断也计为已尝试，不自动重试。加载新资料会使旧结果不再注入，但不会重跑以前的消息。去重记录有界：每会话最近 500 条已完成 ID、最近 128 会话，最多 256 批结果；不是永久全量聊天档案。待处理消息的文字完成后清除，参考片段仍保存在私有批次结果中。

向量结果先满足最低相似度，再排除比最佳候选低超过 `embedding.relative_margin`（默认 0.08）的片段；最多两段事实或一段风格。关键词风格查询只使用当前消息主题，未命中可不注入。相似度不是正确率，这些限制会减少弱相关结果，也可能漏掉间接相关内容。世界短码按完整代码约束，多个代码必须在同一候选中均出现。

## 风格与情境

“为批次内消息检索风格”开启时，每条查询会附带该消息的情境；关闭后仅显式谈及语气、风格等才查。embedding 根据语义相似度选择语录，关键词模式按词匹配。没有独立的情绪分类或准确理解承诺，也不会把整份语录全部注入。

建议常驻人设保留核心性格、称呼和表达边界；详细例句可放 Q 文档按需召回。不要完全删除常驻风格：不足一批、未命中、后台未完成或服务失败时，仍需常驻设定保持角色稳定。可在 Q 文档中用“安慰/争执/日常闲谈”等场景标题，提升可检索性。

## 向量、开销与数据范围

向量使用宿主 embedding 任务及密钥，不调用额外生成模型。构建和查询会产生 embedding 请求，具体价格取决于宿主服务。未构建、禁用、失效或请求失败时使用本地关键词。模型配置热更新会使当前向量失效，需手动重建；SDK 不能可靠识别同名配置在离线期间更换服务，若你换了 embedding 模型也请手动重建。

最低余弦相似度不是正确率，默认 0.4 需要结合自己的检索结果调整。世界短码要求候选正文精确包含，避免 C8 直接混为 C5；同一片段含多个代码仍需模型判断关系。

每阶段最多注入 2200 字符，风格占独立小预算；字符不是 token。默认两批并发、单批超时 120 秒；大批次遇到慢服务可能只完成部分消息。失败继续原请求。

资料对所有允许会话共享；私密资料应限制“允许会话 ID”（宿主 session_id，非 QQ 群号）。默认关闭宿主记忆回退，避免取回共享库的旧文档；开启后遵守会话和宿主过滤，但宿主只返回短文本，无法按来源严格筛选。

本插件不写共享记忆，不做显式归档，也不阻止资料被聊天复述后由原有摘要流程再次记忆。私有数据目录包含资料快照、向量和批次记录，分享时只分享代码包，不分享私有数据。参考片段是普通请求数据，不能覆盖后台身份认证或授权。
